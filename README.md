# 接龙小账：使用说明

这是一个可操作的网页原型，已导入提供的 24 位顾客接龙。当前在本机运行，暂未发布到互联网，也不是已上线的微信小程序。

## 开始使用

当前预览地址：http://127.0.0.1:5173/

如果预览停止，可在当前电脑双击“启动本地工具.cmd”，并在浏览器打开上述地址。启动窗口运行期间请保持打开。源代码安装在同目录；启动脚本使用当前电脑的 Codex Node.js 环境。

1. 在“商品与价格”设置真实价格、计价单位，并确认待定的口味规则。
2. 在“订单核对”点击顾客的“核对订单”，对照原文检查数量、单位、口味、取货点和切配备注。
3. 点击“发给顾客核对”，把复制的文字粘贴到微信群。顾客回复后修正订单，再点击“顾客已核对，确认”。工具不会自动发送消息。
4. “采购清单”只汇总已确认订单，按商品、口味和单位分别计算，可导出 CSV。
5. 在“取货核销”按取货点筛选，确认领货后点击“确认取货”。误点可以撤销，保留时间与操作记录。

修改已确认订单会取消确认状态，需再次核对。修改已领取订单还会取消领取状态。

## 当前规则及需核对事项

- 金额暂按日元计，跑腿费默认每位顾客 200，可修改或设为 0。
- 商品价格未提供，默认空白；不是 0。价格、数量或计价单位不完整时，总价显示待定。
- 不注明口味默认为不辣。内脏暂设为仅辣；鱼丸、烧鸡、鸭胗、干豆腐的具体口味规则需要采购者确认。冷冻属于保存方式，不能推断为原味。“五香类仅不辣”可在新增商品中选择“仅不辣”。
- 所有解析结果都需人工核对。数量未写不猜为 1，单位未写标待确认。1kg 和 1份分别计数。
- 鱼丸套餐与丸子组合保持独立；鸭珍暂映射为鸭胗并标提示；大岛麻辣烫店保留独立待确认取货点。
- 自由新增商品和别名。不在商品目录里的商品需要先新增，再解析或在订单中补录。
- 接龙导入是追加操作，不要重复导入同一份内容。目前一次团购支持最多 500 单。

## 数据与完成范围

本地预览的数据保存在本机的 D1/SQLite 数据库（.wrangler/state），不是微信群数据自动同步。重启服务后可继续读取；不要删除该目录。云端部署的数据库与本地数据库是独立的。

已实现：接龙规则解析、原文核对、编辑订单、确认后采购汇总、设置商品与价格、按点核销与撤销、操作记录、版本冲突检测、桌面及手机响应布局。

未完成：线上发布、微信群自动读取、顾客身份认证及顾客自行打开链接修改、微信小程序发布。当前顾客核对通过复制清单到微信群，再由采购者更新订单完成。不能把本机地址直接分享给群成员使用。

发布尝试被环境自动审批拒绝：向发布进程提交标准输入时要求沙箱审批，而当前策略不允许该审批。已注册的私有站点保留在 .openai/hosting.json，尚无成功发布地址。后续应复用这个站点，不能重复注册。

## 开发与验证

技术：React + Vinext + Shadcn UI，Cloudflare D1。业务逻辑：lib/orders.ts；页面：app/board.tsx；数据接口：app/api/board/route.ts；数据库结构：db/schema.ts。

已通过 TypeScript 检查、本地应用构建、24条接龙解析及口味/单位测试、编辑与金额计算、保存回读、取货与撤销、版本冲突及负数量拒绝测试。浏览器检查了核对界面和 390px 手机布局，并验证 WebMCP 只读汇总工具及无效输入拒绝。

源码压缩包不包含 node_modules 或本地订单数据库；此电脑目录中已安装依赖。迁移到其他环境需安装 Node.js 22.13+ 与 npm，运行 npm ci，再生成构建和应用数据库迁移。线上供多人使用前需要增加顾客身份与角色权限。
